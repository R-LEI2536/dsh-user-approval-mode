分桶：送审前，先把受闸的子调用从程序里剥出来

PTC 下模型只能直调 run_code，一段 JS 程序里混着两种代码： 受闸的 tools.* 子调用（执行时以真实工具名、真实参数值各自重新过闸） 和直接代码（import、直调、数据拼装——只有分类器能裁的部分）。 分桶器把两者分开：LLM 分类器收到的是剥掉子调用的程序，占位符保留数据流形状； 有任何掉包嫌疑就放弃分桶，整段原文交给它。

生效范围
仅 smart 模式 · 仅 LLM 分类器的 evidence；request / auto-edit 弹窗看的仍是原文
不变量
危险清单匹配文本、会话记忆 key、弹窗 [code: …] 摘要永远用原始程序
失败方向
放弃分桶 = 分类器看到更多、不会更少；宁可少剥，不可剥错
日志
每次分桶 / 放弃一行可 grep：[dsh-user-approval[run-code-strip]]
模型发起顶层 run_code 调用（.code = 完整 JS 程序）
↓五步流水线开始

①危险清单

13 条正则扫「调用理由 + 完整参数 JSON」——程序原文就在其中，藏在子调用参数里的字面灾难（rm -rf /、force-push…）在这里就拦下。

→
命中 ⇒ ask 转人工
pattern=<正则>
↓未命中

②代码结构闸门 run-code-gate

acorn 解析，两档语法：严格档（纯 tools.* 程序）永远放行；宽档（纯表达式、受识别控制流、白名单方法）按 runCodePureExpressions 开关放行。

→
识别 ⇒ 放行
不调 LLM，源码不出本机；子调用各过各闸
↓未识别（含遮蔽 tools、解析失败）——落给后面各步

③会话记忆

key = sha256("run_code\n" + 原始程序)。同一程序 30 分钟内重跑不再问 LLM——记忆按原文匹配，分桶不影响它。

→
命中 ⇒ 放行
source=remembered
↓未命中

④分桶器 run-code-strip

本页主角：把程序按「受闸子调用 / 直接代码」分成两桶，只有直接代码进 evidence。

干净 ⇒ 剥

  • 每个 tools.x(…) / await tools.x(…) 换成 [gated sub-call]
  • 嵌套子调用随外层一次剥掉（外层优先）
  • computed（tools['x']）、可选链（tools?.x）、别名调用不剥、留在原地

有疑虑 ⇒ 放弃（六种）

  • 任何位置绑定名字 tools
  • eval / Function 引用
  • 动态 import()
  • 任何成员写入（含 globalThis、computed 写、delete）
  • Object.assign / defineProperty / Reflect.set 等劫持面
  • 解析失败或内部异常
⇢
放弃 ⇒ 原文整段发给分类器
decision=abort reason=<why>（安全方向：只会多看，不会少看）
↓剥完（或放弃后）进证据拼装

⑤Evidence 拼装

command
分桶后的程序（放弃时 = 原文）
toolArguments
null —— 程序已随 command 走，不再整段重发第二遍 （去重，也是分桶成立的前提）
justification
提权理由（若有）
workspacePath
会话工作区
latestUserMessage
最新真实用户消息（唯一可信字段）
一次性 JSON
evidence 以单一 user message 发给 LLM
↓

⑥LLM 分类器

审的是直接代码桶：import、直调、数据拼装。子调用的操作风险不在它的职责里——每个子调用执行时有自己的闸门、看的是拼装完成的真实值。

→
approve ⇒ 放行 + 写记忆
decision=allow detail=classifier
↓ask / 超时 / 协议错 ⇒ ask 转人工（fail-safe 全部向下）
程序开始执行

执行期：占位符只是投影，真实程序照跑

分桶只改「发给分类器看的那份文本」。被放行的程序以原文执行，每个 tools.* 子调用带着 parent、真实工具名与真实参数值重新进入同一个 tools/pre-execute 闸门：

子调用的闸门（与顶层无关，照旧）

  • tools.read → 只读族免检
  • tools.bash → 五步流水线（危险清单 → 只读 git 快路径 → 记忆 → 分类器 → fail-safe）
  • tools.write → 按模式表（request 下弹窗等）
  • 被拒只抛该绑定的 ToolCallError，重试重新过闸

永远看原文的三处

  • 危险清单的匹配文本（步骤 ①）
  • 会话记忆的 key（步骤 ③）
  • 弹窗 [code: …] 摘要——用户要看真程序，不是剥过的

日志样例

[dsh-user-approval[run-code-gate]]   decision=allow detail=tools-only
[dsh-user-approval[run-code-strip]] decision=strip count=2
[dsh-user-approval[run-code-strip]] decision=abort reason=shadow
[dsh-user-approval[smart]]          decision=allow detail=classifier model=… provider=…
[dsh-user-approval[smart]]          decision=ask detail=model-returned-ask model=… provider=…
放行 转人工 放弃分桶（安全方向） 本页主角
